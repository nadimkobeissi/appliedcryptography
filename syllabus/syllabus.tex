\section*{Course Syllabus}

\textit{Applied Cryptography} explores the core theory of modern cryptography and how to apply those principles to build and analyze secure systems. We start with foundational concepts: Kerckhoffs' principle, computational hardness, and provable security. From there we move to the primitives themselves, including pseudorandom generators, block ciphers, and hash functions. We then survey how these technologies power real-world deployments such as TLS, secure messaging protocols (e.g., Signal), and post-quantum cryptography, along with specialized topics like high-assurance implementations, elliptic-curve-based systems, and zero-knowledge proofs. By the end of the semester you will have a rigorous theoretical perspective and the hands-on experience to evaluate and build cryptographic systems.

\section{Course Objectives \& Outcomes}
This course connects the theoretical foundations of cryptography to their practical use in contemporary secure systems. Through the lectures, problem sets, and project work, you will learn the concepts of modern cryptography and gain the skills to implement and assess security solutions.

Upon successful completion of this course, a student should be able to:

\begin{itemize}
	\item Understand the reasoning behind the mathematics that modern cryptography is built on.
	\item Analyze and prove the security properties of cryptographic constructions.
	\item Understand how cryptographic constructions can be composed to build secure protocols and systems.
	\item Distinguish between the mathematical and engineering approaches to cryptography.
	\item Critically assess security implementations and evaluate real-world cryptographic protocols.
	\item Form a view of where cryptography is heading and the role it plays in emerging technologies.
\end{itemize}

\section{Assessment Items \& Grading Criteria}
Your performance is evaluated through several components that measure both your theoretical understanding and your practical skill. Stay current with the readings, participate in lectures and projects, and complete all assigned work, and you will come out knowing the material.

Each course component assesses a different learning outcome, and students are expected to meet all learning outcomes. There will be no dropping of low assignment grades and no shifting of percentages across different course components.

\subsection{This Is Your Classroom}
This course is built around you producing work that is entirely your own, without resorting to AI technologies. That keeps your learning yours, and it makes grading fairer for everyone. The class sessions and projects therefore favor \textbf{engagement}:

\begin{itemize}
	\item \textbf{Interactive lectures:} Classes include exercises, discussions, and group problem-solving.
	\item \textbf{Real-time feedback:} Low-stakes activities give students regular chances to show what they understand and to hear back immediately.
	\item \textbf{Peer teaching:} Students will occasionally be asked to explain concepts to their peers, which reinforces their own understanding.
	\item \textbf{Project progress discussions:} Students are encouraged to discuss their progress openly as they work, so that problems get solved while the projects are still moving.
	\item \textbf{Security strategy workshops:} Students present their approaches to implementing security goals and get feedback from peers and instructors to refine them.
\end{itemize}

\subsection{Problem Sets}
Problem sets are assigned periodically through the semester to reinforce the lecture material. Each set mixes theoretical proofs and problem-solving with short coding tasks or computational experiments, so that the theory always has something concrete attached to it. Start each set early, and come to office hours or project sessions if you get stuck.

\subsection{Projects}
Take-home projects are the hands-on complement to the lectures. Each group of one to three students picks one (or, if you're feeling adventurous, at most two) project topics and works on them throughout the entire course. You will experiment with widely used libraries and simulate attacks or vulnerabilities to see why certain security practices are necessary, and you will get comfortable with the surrounding tooling, including formal analysis tools. Take-home projects are mandatory.

Example projects include:

\begin{itemize}
	\item \textbf{Designing a Password Manager:} Implement master password protection, key derivation, password generation, and encrypted storage for sensitive data. You will then analyze where such a system can be attacked and build countermeasures.
	\item \textbf{Designing a Secure Messenger:} Build an end-to-end encrypted messaging application, using cryptographic libraries for key exchange, message encryption, and authentication. The project covers perfect forward secrecy, deniability, and secure group messaging, and runs into the practical problems of key verification and metadata protection.
	\item \textbf{Protocol Modeling and Verification with ProVerif:} Design a Transport Layer Security (TLS)-like protocol and verify it in ProVerif, a formal verification tool for cryptographic protocols. You will specify the security properties a network protocol needs (confidentiality, integrity, authentication) and prove that your design has them.
	\item \textbf{Designing a Battleship Game Using Zero-Knowledge Systems:} Implement battleship on RISC Zero, a zero-knowledge virtual machine (zkVM), so that players can validate each other's moves without revealing the game state. The result is a working introduction to zero-knowledge proofs, zkVMs, and cryptographic protocol design.
	\item \textbf{Post-Quantum Cryptography Migration:} Migrate an existing system to NIST's standardized post-quantum algorithms, integrating ML-KEM (Kyber) for key encapsulation and ML-DSA (Dilithium) for digital signatures. You will measure what that costs in performance and message size, and what the integration work looks like when pre-quantum primitives come out.
	\item \textbf{Private Set Intersection for Contact Discovery:} Build a privacy-preserving contact discovery system on Private Set Intersection (PSI), using an approach based on an Oblivious Pseudorandom Function (OPRF). You will design the wire protocol, write both the server and the client, and defend against offline enumeration with peppered hashing and rate limiting.
	\item \textbf{Privacy-Preserving Age Verification:} Use cryptographic commitments and signatures to prove age thresholds without revealing anything else about the holder. You will implement zero-knowledge proofs for statements like ``I am 18 or older,'' then handle what makes such a system deployable: credential revocation, credential sharing, and verification fast enough to run on a phone.
	\item \textbf{Building a Time-Locked Message Capsule:} Encrypt a message so that it cannot be decrypted before a chosen future time. You will implement the tlock protocol on the League of Entropy's distributed randomness beacon, with applications including scheduled disclosures, commitment schemes for auctions, and ``digital time capsules'' for personal messages.
\end{itemize}

\section{The Key Exchange}
\textit{The Key Exchange} is an optional weekly gathering for students who intend to become researchers or professionals in cryptography. We read recent research papers, practice presenting complex ideas, work on scientific writing, and talk about career paths. It is meant to be a low-stakes room: questions are encouraged, and someone debugging their first encryption routine is as welcome as someone designing a new protocol. There is no prerequisite beyond curiosity.

The sessions are relaxed and coffee-shop-style. You will practice reading a paper efficiently, presenting a technical idea clearly, writing like a cryptographer, and making career decisions with confidence. One week that might mean discussing elliptic curves with a visiting researcher from Signal, the next it is feedback on your talk about side-channel attacks, and the week after it is a blog post explaining zero-knowledge proofs to a general audience.

\subsection{Four-Week Rotating Schedule}

\subsubsection*{Week 1: Paper Reading Group}
\textbf{Theme:} \textit{Reading and Understanding Research}

We read cryptography papers together: classics sometimes, but more often whatever just came out of CRYPTO, Eurocrypt, or CCS, along with accessible papers that have clear practical applications. You will learn a reading order that works (abstract $\rightarrow$ contributions $\rightarrow$ methodology $\rightarrow$ conclusion), practice spotting what a paper actually contributes and where it falls short, and annotate as a group.

\textbf{Skills developed:} Critical analysis, technical reading comprehension, identifying research gaps

\subsubsection*{Week 2: Student Presentations}
\textbf{Theme:} \textit{Communicating Complex Ideas}

Give a 15-minute talk on a cryptographic topic and get peer feedback on it. A talk can explain a construction, analyze a recent attack, report project progress, or pitch a research idea. We will also run ``lightning talks'' for 3-minute research pitches, and practice with visual aids and demos.

\textbf{Skills developed:} Public speaking, slide design, handling Q\&A, time management

\subsubsection*{Week 3: Writing Workshop}
\textbf{Theme:} \textit{Scientific Writing and Documentation}

Work on your technical writing through group exercises and peer review. Projects include writing abstracts for imaginary papers, blog posts explaining crypto concepts, security audit reports, and research proposals. We will also cover LaTeX for papers and how to write a security disclosure.

\textbf{Skills developed:} Technical writing clarity, academic writing style, documentation conventions, peer review skills

\subsubsection*{Week 4: Career Café}
\textbf{Theme:} \textit{Professional Development and Pathways}

We host industry guest speakers (virtual or in-person), run graduate school application workshops and interview preparation, and review portfolios and CVs. The conversation covers industry versus academia, what different roles actually require, and how to build a network.

\textbf{Skills developed:} Professional networking, interview skills, career planning, industry awareness

\section{Course Policies}
Students are expected to strictly observe the following course policies:

\subsection{Attendance}
\textbf{Do not register for this course if you do not plan to attend all classes and exams.} You are expected to abide by the classroom's rules on attendance. You are expected to attend lectures and to be on time for all sessions and activities related to this course. Lectures are a sequence. Missing one lecture will almost certainly mean that you will not be able to keep up with the following lectures without studying the material covered in the missed lecture. Catching up with missed lectures is your responsibility and is done on your own time. You are responsible for all work, even when absent. Attendance may be recorded at every class session. Excessive absence, defined at the discretion of the instructor, will not be tolerated and will result in being dropped from the course.

\subsection{Academic Misconduct \& Plagiarism}
Lectures start on time. You may not be allowed to come into the room once class has started. Any class conduct that disturbs the learning atmosphere may be deemed misbehavior and will not be tolerated.

This course has a strict \textbf{zero tolerance policy for cheating}. Any instance of cheating will result in an immediate, non-negotiable grade of 0 on the pertinent assignment.
\begin{itemize}
	\item Your work has to be your own. No copying work (or rewriting it line by line based on someone else's work) will be tolerated.
	\item Any sharing of any answers on any assignment is considered cheating.
	\item Coaching another student by helping them write their answers line by line is also cheating.
	\item Copying answers or code from the Internet or hiring someone to write your answers for you is cheating.
\end{itemize}

Explaining how to use systems or tools and helping others with high-level design issues is not cheating.

\subsubsection{Regarding AI Tools}
Any use of AI tools to produce answers to class assignments or projects is considered cheating.
\begin{itemize}
	\item Using AI tools like ChatGPT, GitHub Copilot, or similar to generate code, proofs, or written answers constitutes cheating.
	\item Submitting AI-generated work without proper attribution and explanation is considered plagiarism.
	\item The course will use AI-detection tools and manual review to identify AI-generated submissions.
	\item Using AI to help you learn (e.g., asking ChatGPT questions about the material) is not considered cheating.
\end{itemize}

The Student Code of Conduct\footnote{\urlcodeofconduct} acts as the main reference in determining instances of misconduct.

\subsubsection{Your Instructor's Views on Cheating}
I regard cheating in my course as a fundamental moral offense and quite possibly the single greatest insult you can commit towards your peers, who are all toiling in order to earn their grade honestly, and towards myself, as someone who has consecrated significant effort towards preparing and delivering this course and towards helping you develop new intellectual and practical skills. When asking yourself how I will react to instances of cheating, imagine the strictest possible scenario, multiply it a hundredfold, then square it with itself, and then realize that this actually doesn't even cover a fraction of how I will interpret instances of cheating. I will answer any instance of cheating with a fanatical zeal so exaggerated that you will certainly never in your life cheat again.
